# Module 0: Prestudy — Comprehensive Analysis & Research Rationale

---

## Executive Summary

**Module 0: Prestudy** serves as the empirical and architectural cornerstone of the **Dravidian Language LLM Fine-Tuning Study**. Using the 14-billion parameter foundation model `microsoft/phi-4`, this research explores the feasibility, efficiency, and retention dynamics of adapting large English-centric models to two morphologically complex, non-Latin Dravidian languages: **Kannada** and **Telugu**.

Before deploying hundreds of hours of high-performance GPU compute across Supervised Fine-Tuning (Module 1), Continual Learning (Module 2), and Multilingual Adapter Fusion (Module 3), Module 0 rigorously established:
1. **Data Hygiene & Integrity**: A leak-free, script-pure, deduplicated instruction-tuning corpus of 40,000 samples.
2. **Subword Tokenizer Mechanics**: An empirical characterization of token fragmentation and vocabulary fertility under the tiktoken BPE tokenizer.
3. **Zero-Shot Foundation Baselines**: Controlled benchmarks across translation quality (chrF++, BLEU), semantic fidelity (COMET, BERTScore), language modeling perplexity, and inference runtime characteristics on FLORES-200.

This document provides an exhaustive explanation of **why** this prestudy was conducted, **how** it was executed, **what** empirical findings were discovered, **what** was achieved, and **how** it directly guided and enabled the downstream modules.

---

## 1. Why Did We Do This? (Motivation & Problem Statement)

### 1.1 The Challenge of Adapting Foundation LLMs to Dravidian Scripts
State-of-the-art foundation models like `microsoft/phi-4` are pre-trained predominantly on English, Western languages, and source code. Dravidian languages (spoken by over 250 million people across Southern India) present fundamental linguistic differences:
* **Agglutinative Morphology**: Root words are compounded with multiple grammatical suffixes, creating long, information-dense lexical units.
* **Abugida Writing Systems**: Unlike the Latin alphabet, Dravidian scripts are phonetic syllabaries where consonants combine with vowel matras and conjunct sub-glyphs (viramas) to form complex orthographic units called *aksharas*.
* **Under-Representation in Vocabulary**: Web-crawled pre-training datasets contain minuscule fractions of native Kannada and Telugu text compared to English.

### 1.2 The High Cost of Uncalibrated Fine-Tuning
Fine-tuning a 14B parameter model across multiple strategies (Full Fine-Tuning, LoRA, DoRA, QLoRA, IA³) requires massive compute budgets (over 219 active GPU hours in Module 1 alone). Entering fine-tuning without prior analysis introduces critical failure modes:
* **Garbage-In, Garbage-Out**: Web-sourced instruction datasets often contain Romanized text, code-switched English sentences, machine-translation artifacts, and duplicated records. Training on impure data degrades generative alignment.
* **Context Budget Collapse**: If the tokenizer fragments Dravidian words into dozens of subwords, standard context windows (e.g., 1024 or 2048 tokens) can silently truncate instructions or prompt templates.
* **Lack of a Scientific Control Group**: Without evaluating the unmodified, zero-shot base model on the exact same test benchmarks, it is impossible to quantify whether downstream fine-tuning actually produced new linguistic capabilities, merely aligned formatting, or caused catastrophic damage.

---

## 2. Importance of Doing the Prestudy

1. **Elimination of Data Leakage**: In academic benchmarking, overlap between training instructions and evaluation benchmarks invalidates claims of generalisation. SHA-256 cryptographic deduplication guarantees strict separation.
2. **Tokenizer Health Audit**: Understanding whether the tokenizer uses native script tokens or falls back to raw byte representations (`<0xNN>`) dictates whether vocabulary expansion or byte-level training is required.
3. **Establishing the Experimental Anchor**: Every scientific claim in Module 1 (Pareto improvement), Module 2 (catastrophic forgetting delta), and Module 3 (merging vs. base retention) requires a ground-truth baseline to compute positive or negative transfer.

## 3. How Was It Done? (Technical Methodology & Implementation)

Module 0 is divided into four sequential, automated components:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Module 0: Prestudy Pipeline                     │
├───────────────────────────────┬────────────────────────────────────────┤
│ 1. Dataset Prep               │ Downloads Indic-Align, filters script  │
│    (dataset_prep.py)          │ purity (≥0.70), deduplicates SHA-256,  │
│                               │ balances 18k train / 1k val / 1k test  │
├───────────────────────────────┼────────────────────────────────────────┤
│ 2. Fertility Analysis         │ Measures tokens/word, byte-fallback,   │
│    (fertility_analysis.py)    │ and UNK rates vs English control       │
├───────────────────────────────┼────────────────────────────────────────┤
│ 3. Baseline Evaluation        │ Zero-shot FLORES-200 benchmark of raw  │
│    (base_eval.py)             │ Phi-4 (chrF, BLEU, PPL, Latency, VRAM) │
├───────────────────────────────┼────────────────────────────────────────┤
│ 4. Verification Gates         │ Automated pytest assertions verifying  │
│    (test_prestudy.py)         │ row counts, purity, schemas, & zero-leak│
└───────────────────────────────┴────────────────────────────────────────┘
```

### 3.1 Dataset Preparation Pipeline (`dataset_prep.py`)
* **Raw Corpus**: Sourced from `ai4bharat/indic-align`, focusing strictly on high-hygiene human-translated subsets: `Dolly_T` and `OpenAssistant_T`.
* **Unicode Script Boundaries**:
  * Kannada code points: `U+0C80` through `U+0CFF`
  * Telugu code points: `U+0C00` through `U+0C7F`
* **Script Purity Metric**:
  $$\text{Script Purity} = \frac{\text{Count of characters within target Unicode range}}{\text{Total alphabetic characters in text}}$$
  All samples with purity $< 0.70$ were discarded.
* **Cryptographic Deduplication**:
  A SHA-256 digest was generated for every `instruction + output` string. Identical hashes were eliminated across all splits.
* **Proportional Stratified Sampling & Partitioning**:
  * Kannada: 18,000 train, 1,000 val, 1,000 test (20,000 total)
  * Telugu: 18,000 train, 1,000 val, 1,000 test (20,000 total)
  * Dataset balance ratio: Exactly **1.00** across both languages.

### 3.2 Tokenizer Fertility Analysis (`fertility_analysis.py`)
* Evaluated 500 texts per language alongside an English control group (500 samples from `tatsu-lab/alpaca`).
* Computed:
  * **Tokens Per Word (TPW)**: $\frac{\text{Length of token IDs}}{\text{Word count}}$
  * **Byte-Fallback Rate**: Proportion of hex byte tokens (`<0xNN>`) generated when characters lack BPE merges.
  * **Unknown Token Rate**: Occurrences of `<unk>`.

### 3.3 Zero-Shot Foundation Model Evaluation (`base_eval.py`)
* Evaluated unmodified `microsoft/phi-4` (14.66B parameters, BF16) on the gated FLORES-200 devtest set (`kan_Knda` and `tel_Telu`).
* Executed through the unified evaluation engine (`evaluation/eval_engine.py`):
  * **chrF++ & BLEU**: Character and word n-gram matching via `sacrebleu`.
  * **Perplexity (PPL)**: Exponentiated cross-entropy loss over validation text sequences:
    $$\text{PPL} = \exp\left(-\frac{1}{N} \sum_{i=1}^N \log P(x_i \mid x_{<i})\right)$$
  * **Semantic Metrics**: BERTScore F1 (multilingual embeddings) and COMET (`Unbabel/wmt22-comet-da`).
  * **System Metrics**: Peak VRAM allocation, batch-size 1 latency, and batch-size 8 token throughput.

## 4. What Did We Find? (Empirical Findings & Analysis)

### 4.1 Tokenizer Subword Fertility Findings

| Language | Sample Size | Mean Tokens/Word | Std Dev | Min | Max | Byte-Fallback Rate | UNK Rate |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **English** | 499 | **1.43** | 0.56 | 1.00 | 7.00 | 0.0% | 0.0% |
| **Kannada** | 500 | **14.44** | 2.62 | 3.50 | 28.00 | **0.0%** | **0.0%** |
| **Telugu** | 500 | **13.30** | 2.16 | 2.33 | 31.33 | **0.0%** | **0.0%** |

#### Key Insights:
1. **The 10× Token Inflation Factor**:
   Phi-4 produces **14.44 tokens/word** for Kannada and **13.30 tokens/word** for Telugu, compared to just **1.43 tokens/word** for English. A paragraph of 100 Dravidian words requires ~1,350 to 1,450 tokens. This reduces the effective context window of the model by a factor of 10.
2. **Akshara Grapheme Segmentation**:
   Because BPE merges for Dravidian scripts are sparse in the English-dominated vocabulary, the tokenizer breaks words down into individual base consonants, vowel signs (matras), and viramas.
3. **0.0% UNK Rate and 0.0% Byte-Fallback Rate**:
   * The tiktoken-based tokenizer does not have `<unk>` tokens; any out-of-vocabulary character can fall back to raw byte tokens (`<0x00>` to `<0xFF>`).
   * The **0.0% byte-fallback rate** proved that the Unicode code points for Kannada (`0C80`–`0CFF`) and Telugu (`0C00`–`0C7F`) were already indexed in the tokenizer's base character set. The model can process the scripts natively without requiring embedding vocabulary modification.

### 4.2 Zero-Shot Foundation Baseline Performance

| Metric | Kannada Baseline | Telugu Baseline | Linguistic / Computational Meaning |
| :--- | :---: | :---: | :--- |
| **chrF++** | **22.58** | **23.76** | Raw character n-gram overlap on FLORES-200 |
| **BLEU** | **2.95** | **3.09** | Word-level n-gram overlap (virtually non-functional) |
| **Perplexity (PPL)** | **1.65** | **1.68** | Internal language modeling confidence on text |
| **COMET** | 0.5663 | 0.5679 | Neural machine translation quality estimation |
| **BERTScore F1** | 0.5411 | 0.5354 | Semantic embedding alignment |
| **Script Purity (Output)** | 0.8644 | 0.9095 | Generation script consistency |
| **Peak VRAM** | 32.90 GB | 31.80 GB | Memory required to load base model (BF16) |
| **Inference Latency (bs=1)** | 4375.22 ms | 3349.31 ms | Generation latency per sequence |
| **Throughput (bs=8)** | 57.25 tok/s | 71.84 tok/s | Generation speed under batching |

#### The Core Paradox: Reading Familiarity vs. Writing Alignment
* **Low Perplexity (~1.65)**: The base model predicts Dravidian characters with low perplexity. During pre-training web crawling, the model saw enough Dravidian text to learn transition statistics and spelling.
* **Low BLEU (~3.0)**: Despite low perplexity, the model cannot perform semantic translation or follow instructions in Dravidian scripts. It has representation in its weights but completely lacks task alignment.
* **Conclusion**: SFT is mandatory. The base model has the raw capacity, but requires adapter alignment to unlock practical utility.

### 4.3 Throughput & Latency Discrepancy
* Telugu demonstrated **higher throughput (71.84 tok/s)** and **lower latency (3349.31 ms)** than Kannada (**57.25 tok/s / 4375.22 ms**).
* This directly reflects the lower fertility rate of Telugu (13.30 vs 14.44 tokens/word), requiring fewer autoregressive decoding steps for equivalent semantic content.

### 6.1 Impact on Module 1 (Monolingual Fine-Tuning)
1. **Validation of SFT Necessity**:
   By establishing the zero-shot baseline (chrF ~22.6–23.8, BLEU ~3.0), Module 1 demonstrated huge quantitative leaps across all 5 techniques:
   * **Full Fine-Tuning (FFT)**: Pushed chrF to **28.46** (Kannada) and **29.08** (Telugu), with BLEU rising to **4.45** and **5.33**.
   * **LoRA & DoRA**: Reached competitive chrF (~26.1–27.5) with only 0.15% trainable parameters.
2. **Context Window Configuration**:
   The fertility analysis confirmed that 1024 tokens was the optimal context length for SFT, preventing VRAM out-of-memory errors on A100 GPUs while capturing >99.9% of full dialogues.
3. **Elimination of Vocabulary Expansion Complexity**:
   Because byte fallback was 0.0%, researchers avoided modifying embedding matrix dimensions (which would have broken pre-trained weight alignments and prevented PEFT adapters from functioning cleanly).

### 6.2 Impact on Module 2 (Sequential Fine-Tuning & Continual Learning)
1. **Ground Truth for Continual Learning Metrics**:
   Module 2 evaluated whether fine-tuning Telugu FFT sequentially on Kannada retained Telugu capability. Module 0's baseline provided the critical anchor:
   * Telugu FFT started at chrF **29.08**.
   * After sequential Kannada training, Telugu collapsed to **0.4198** (a **98.6% capability destruction**, Retention = 1.44%, BWT = −28.66).
2. **Revealing Catastrophic Failure Below Base Model**:
   Without Module 0, one might assume the sequential model reverted to base performance. Comparing against Module 0 revealed that **Telugu collapsed far below the un-tuned base model (0.42 vs 23.76)**. Continual FFT actively destroyed the foundational representations that the base model possessed.

### 6.3 Impact on Module 3 (Multilingual Adapter Fusion)
1. **Benchmark for Zero-Training Bilingual Models**:
   Module 3 evaluated post-hoc weight merging (TIES-Merge vs. Linear Average) of separate Kannada and Telugu LoRA adapters on CPU at zero additional training cost.
2. **Proving Adapter Merging Exceeds Base Foundation Performance**:
   * Module 0 Base Average chrF: **23.17**
   * Module 2 Sequential FFT Average chrF: **12.34** (catastrophic failure)
   * Module 3 Linear Average chrF: **24.79** (Kannada 24.51, Telugu 25.07)
   
   Because Module 0 established the 23.17 base score, Module 3 successfully demonstrated that **Linear LoRA merging surpasses the foundation base model by +1.62 chrF points across both languages simultaneously**, retaining 94% of monolingual performance without requiring any GPU training hours.
