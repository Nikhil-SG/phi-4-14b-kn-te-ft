# Module 2: Sequential Fine-Tuning & Continual Learning — Comprehensive Analysis & Research Rationale

---

## Executive Summary

**Module 2: Sequential Fine-Tuning & Continual Learning** investigates the most critical failure mode in multilingual LLM adaptation: **catastrophic forgetting**. This module answers a fundamental question: *Can a monolingual fine-tuned model learn a second Dravidian language without destroying its first?*

Starting from Module 1's Telugu Full Fine-Tuned (FFT) checkpoint — the strongest monolingual model (chrF 29.08) — Module 2 performed sequential Supervised Fine-Tuning on Kannada data. The results were devastating and scientifically invaluable:
1. **Catastrophic Forgetting Confirmed**: Telugu capability collapsed from **29.08 → 0.42 chrF** (98.6% destruction), a performance level **far below** even the untrained base model (23.76 chrF).
2. **Successful Kannada Acquisition**: Kannada performance rose to **24.26 chrF**, demonstrating that sequential training does teach the new language.
3. **Net Bilingual Failure**: The average bilingual chrF of **12.34** was dramatically worse than the untrained base model's **23.17**, proving that naive sequential FFT is a strictly dominated strategy.

These findings directly motivated Module 3's exploration of parameter-efficient adapter merging as the solution to multilingual deployment.

---

## 1. Why Did We Do This? (Motivation & Problem Statement)

### 1.1 The Multilingual Deployment Challenge

Real-world deployment of LLMs in Southern India requires serving multiple Dravidian languages simultaneously. An organization cannot afford to maintain separate 14.66B parameter model instances for each language. The most intuitive approach — training sequentially on each language's data — must be empirically validated or falsified.

### 1.2 The Catastrophic Forgetting Hypothesis

The continual learning literature has extensively documented **catastrophic forgetting** in neural networks: when a model trained on Task A is subsequently trained on Task B, the gradient updates for Task B overwrite the weight configurations learned for Task A. For foundation LLMs, this manifests as:

$$\text{BWT} = \text{Performance}_{A}^{\text{after B}} - \text{Performance}_{A}^{\text{after A}}$$

Where **BWT (Backward Transfer)** quantifies how much of Task A's capability is retained (positive BWT) or destroyed (negative BWT) after training on Task B.

### 1.3 The Scientific Gap

While catastrophic forgetting is well-documented for closely related languages (e.g., French → Spanish), its severity for **script-disjoint** Dravidian languages has not been systematically measured at the 14B parameter scale. Kannada and Telugu:
* Share common Dravidian linguistic roots and grammatical structures.
* Use **completely different Unicode script blocks** (Kannada: U+0C80–U+0CFF, Telugu: U+0C00–U+0C7F).
* Have distinct akshara inventories and orthographic conventions.

This creates a unique experimental setting: the languages are semantically related but orthographically disjoint, making forgetting dynamics unpredictable.

---

## 2. Importance of Doing Sequential Fine-Tuning Analysis

1. **Falsification of Naive Multilingual Strategy**: If sequential FFT works, it would be the simplest path to multilingual deployment. Proving it fails eliminates a tempting but destructive approach.
2. **Quantifying the Forgetting Severity**: The precise magnitude of capability loss (−28.66 chrF BWT) establishes the empirical gravity of catastrophic forgetting, motivating investment in more sophisticated approaches.
3. **Below-Base-Model Discovery**: The finding that sequential training produces results **worse than the untrained base model** was not a foregone conclusion and has profound implications for deployment safety.
4. **Continual Learning Metric Registry**: FWT, BWT, and Retention metrics establish a formal framework for evaluating any future continual learning strategy applied to this model family.

### 3.2 Training Configuration

| Parameter | Value | Rationale |
| :--- | :---: | :--- |
| **Starting Checkpoint** | Telugu FFT (Module 1) | Best monolingual model to test retention |
| **Training Data** | Kannada 18,000 samples | Module 0 curated, leak-free partition |
| **Training Strategy** | Full Fine-Tuning (FFT) | All 14.66B parameters unfrozen |
| **Context Length** | 1024 tokens | Consistent with Module 1 |
| **Epochs** | 3 | Same as Module 1 for fair comparison |
| **Learning Rate** | 2e-5 | Identical to Module 1 FFT |
| **Optimizer** | AdamW (β₁=0.9, β₂=0.999) | Consistent with Module 1 |
| **Precision** | BF16 | Consistent with Module 1 |
| **LR Scheduler** | Cosine Annealing | Consistent with Module 1 |

### 3.3 Evaluation Protocol

After sequential training completion, the model was evaluated on **both** languages using the same FLORES-200 devtest benchmark:

1. **Kannada Evaluation**: Measures whether the model successfully learned Kannada (Forward Transfer).
2. **Telugu Evaluation**: Measures how much Telugu capability was retained or destroyed (Backward Transfer).

### 3.4 Continual Learning Metrics Framework

Three formal metrics were computed:

**Forward Transfer (FWT)**:
$$\text{FWT} = \text{chrF}_{\text{Kannada}}^{\text{after sequential}} - \text{chrF}_{\text{Kannada}}^{\text{base}}$$
Measures the Kannada capability gained from sequential training, compared to the untrained base model.

**Backward Transfer (BWT)**:
$$\text{BWT} = \text{chrF}_{\text{Telugu}}^{\text{after sequential}} - \text{chrF}_{\text{Telugu}}^{\text{after Telugu FFT}}$$
Measures the Telugu capability change after Kannada training, compared to the Telugu monolingual peak.

**Retention Rate**:
$$\text{Retention} = \frac{\text{chrF}_{\text{Telugu}}^{\text{after sequential}}}{\text{chrF}_{\text{Telugu}}^{\text{after Telugu FFT}}} \times 100\%$$

### 4.3 Detailed Analysis

#### 4.3.1 The Catastrophic Collapse of Telugu

```
Telugu chrF Performance Trajectory:

  30 ┤ ████████████████ Module 1 FFT: 29.08
     │
  25 ┤ ─────────────── Module 0 Base: 23.76
     │
  20 ┤
     │
  15 ┤
     │
  10 ┤
     │
   5 ┤
     │
   0 ┤ █ Module 2 Sequential: 0.42
     └──────────────────────────────────────→
       Base    After TE FFT   After KN Seq
```

The collapse from 29.08 to 0.42 is not a gradual degradation — it represents a **near-total destruction** of Telugu language capability. Key observations:

1. **Script Purity Collapsed to 4.2%**: The model stopped generating Telugu script entirely. When prompted with Telugu, the sequential model produced Kannada characters, garbled Unicode, or English text.
2. **Perplexity Exploded to 8.94**: The model's internal language model for Telugu was catastrophically disrupted. A perplexity of 8.94 means the model is approximately 5.4× more confused about Telugu text than the untrained base model (1.68).
3. **Below Base Model Performance**: The sequential model's Telugu performance (0.42) is **56× worse** than the untrained base model (23.76). This means sequential FFT didn't just fail to preserve Telugu — it actively **destroyed** the foundational Telugu representations that existed in the pre-trained weights.

#### 4.3.2 Why Did This Happen?

The catastrophic forgetting mechanism in sequential FFT operates through **weight overwriting**:

1. **Full Parameter Update**: All 14.66B parameters were updated during Kannada training. Unlike PEFT methods that freeze the base model, FFT allows gradients to modify every weight.
2. **Script-Disjoint Interference**: Kannada and Telugu operate in different Unicode ranges with different character inventories. The attention patterns, embedding activations, and feed-forward computations optimized for Telugu glyphs during Module 1's FFT were overwritten by patterns optimized for Kannada glyphs.
3. **No Replay or Regularization**: The sequential training used only Kannada data without any Telugu replay samples or Elastic Weight Consolidation (EWC) regularization to protect important Telugu parameters.

#### 4.3.3 Modest Kannada Acquisition

Kannada improved from **22.58 (base) → 24.26 (sequential)**, a gain of +1.68 chrF. However, this is notably weaker than Module 1's direct Kannada FFT (28.46, +5.88 over base). This suggests that:

1. The Telugu FFT initialization, while providing a general fine-tuning warm-start, may create **negative interference** with Kannada learning.
2. Starting from a strongly Telugu-aligned model requires the optimizer to first "unlearn" Telugu-specific patterns before learning Kannada ones, wasting training budget.

#### 4.3.4 Bilingual Average: A Dominated Strategy

| Strategy | KN chrF | TE chrF | Avg chrF | Status |
| :--- | :---: | :---: | :---: | :--- |
| Module 0: Base Model | 22.58 | 23.76 | **23.17** | Zero-cost baseline |
| Module 2: Sequential FFT | 24.26 | 0.42 | **12.34** | **Strictly dominated** |

The sequential model's bilingual average (12.34) is **47% worse** than doing nothing at all (23.17). This is a definitive falsification of sequential FFT as a multilingual deployment strategy.

## 5. What Did We Achieve? (Concrete Deliverables)

1. **Definitive Falsification of Sequential FFT**:
   * Empirical proof that sequential Full Fine-Tuning across script-disjoint Dravidian languages causes catastrophic forgetting severe enough to produce results worse than the untrained model.

2. **Continual Learning Metrics Registry**:
   * Formally computed FWT (+1.68), BWT (−28.66), and Retention (1.44%) metrics that can be referenced by any future continual learning research on this model family.

3. **Below-Base-Model Warning**:
   * Documented the critical finding that sequential training doesn't merely "reset" to base performance but actively destroys pre-existing capabilities, constituting a safety hazard for production deployment.

4. **Motivation for Module 3**:
   * The severity of catastrophic forgetting directly motivated the exploration of parameter-efficient adapter merging as a mathematically guaranteed alternative to sequential gradient-based training.

5. **Sequential Model Checkpoint**:
   * The catastrophically-forgotten checkpoint is preserved as a negative reference point for future research into continual learning mitigation strategies.

### 6.1 Impact on Module 3 (Multilingual Adapter Fusion)

1. **Negative Benchmark**: Module 2's bilingual average of 12.34 established the floor. Module 3's merging strategies needed to exceed this trivially low bar, but more importantly, needed to exceed the base model's 23.17 to justify their existence.

2. **Motivation for Non-Gradient Approach**: The catastrophic forgetting result proved that any approach involving sequential gradient updates on full parameters is fundamentally flawed for this task. This directly motivated Module 3's exploration of **post-hoc weight merging** — a technique that combines adapter parameters through algebraic operations (averaging, pruning) rather than gradient descent.

3. **Script-Disjoint Forgetting Insight**: The finding that Telugu representations were not merely degraded but actively destroyed informed Module 3's decision to use **independently trained LoRA adapters** (from Module 1) rather than attempting any form of sequential adapter training.

## 8. Lessons Learned & Implications

### 8.1 For Practitioners
* **Never deploy sequential FFT for script-disjoint languages** without catastrophic forgetting mitigation (replay buffers, EWC, or adapter isolation).
* **Always evaluate both languages** after sequential training — evaluating only the new language would have missed the Telugu destruction entirely.

### 8.2 For Researchers
* **Catastrophic forgetting severity scales with script distance**: Dravidian script-disjoint forgetting (98.6% loss) is far more severe than what's typically reported for Latin-script language pairs.
* **Below-base-model performance is possible**: Sequential training can produce models worse than the original pre-trained checkpoint, a finding with implications for deployment safety and model governance.

### 8.3 For the Study's Narrative
* Module 2 serves as the **pivot point** of the study: it transforms the research question from "How do we train a multilingual model?" to "How do we **combine** monolingual models without training?"
