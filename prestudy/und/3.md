# Module 3: Multilingual Adapter Fusion — Comprehensive Analysis & Research Rationale

---

## Executive Summary

**Module 3: Multilingual Adapter Fusion** is the culminating experimental module of the **Dravidian Language LLM Fine-Tuning Study**. Motivated by Module 2's catastrophic forgetting failure (98.6% Telugu capability destruction under sequential FFT), Module 3 explored **post-hoc weight merging** as a zero-training-cost alternative for building bilingual Dravidian models.

By algebraically combining the independently trained Kannada LoRA and Telugu LoRA adapters from Module 1, this module evaluated two merging strategies:
1. **TIES-Merge (Trim, Elect Sign, Merge)**: A pruning-based merging algorithm that resolves parameter sign conflicts before averaging.
2. **Linear Average Merge**: A simple arithmetic average of adapter weight matrices.

The results established a clear winner and concluded the study's research arc:
* **Linear Average Merge** achieved a bilingual chrF of **24.79** (Kannada 24.51, Telugu 25.07), surpassing the untrained base model by **+1.62 chrF** and retaining **94%** of monolingual LoRA performance — all at **zero additional GPU training cost**.
* **TIES-Merge** underperformed at **22.84** bilingual average, slightly below the base model, due to aggressive weight pruning that discarded fine-tuning signal.

Module 3 proved that **adapter merging solves the multilingual deployment problem** that sequential training could not, establishing a practical path to simultaneous Kannada-Telugu inference with a single model.

## 1. Why Did We Do This? (Motivation & Problem Statement)

### 1.1 The Problem Module 2 Left Unsolved

Module 2 conclusively demonstrated that sequential Full Fine-Tuning causes catastrophic forgetting: training a Telugu-aligned model on Kannada destroyed 98.6% of Telugu capability, producing bilingual performance (12.34 chrF) far worse than the untrained base model (23.17 chrF).

This left a critical unsolved problem: **How can a single model serve both Kannada and Telugu without catastrophic interference?**

### 1.2 The Adapter Merging Hypothesis

Parameter-efficient fine-tuning (PEFT) methods like LoRA store language-specific adaptations in small, isolated adapter weight matrices rather than modifying the full base model. This architectural separation creates a unique opportunity:

> If language-specific knowledge resides in separate adapter matrices, can these matrices be **algebraically combined** to produce a single bilingual adapter — without any additional gradient-based training?

This hypothesis is grounded in the observation that LoRA adapters occupy a low-rank subspace of the full weight space. If the Kannada and Telugu subspaces are sufficiently orthogonal (i.e., the languages activate different dimensions of the adaptation space), their union should not cause destructive interference.

### 1.3 The Practical Advantage

Adapter merging offers three transformative advantages over sequential training:

| Property | Sequential FFT | Adapter Merging |
| :--- | :--- | :--- |
| **Training Cost** | ~45 GPU-hours per language | **0 GPU-hours** (CPU-only arithmetic) |
| **Forgetting Risk** | Catastrophic (98.6% loss) | **None** (no gradient updates) |
| **Reversibility** | Irreversible weight overwriting | Fully reversible (original adapters preserved) |
| **Scalability** | O(n) training runs for n languages | O(1) merge operation for any n adapters |

## 2. Importance of Doing Adapter Fusion

1. **Solving the Central Research Question**: The study's overarching goal was to find a practical path to multilingual Dravidian LLM deployment. Module 3 provides the answer.
2. **Zero-Cost Bilingual Models**: If merging works, organizations can deploy bilingual models without any additional compute investment beyond the monolingual training already performed in Module 1.
3. **Scientific Comparison of Merging Algorithms**: TIES-Merge and Linear Average represent fundamentally different approaches (pruning-based vs. direct averaging), and their relative performance on Dravidian adapters has not been previously documented.
4. **Closing the Research Arc**: Module 3 completes the narrative: Base → SFT → Sequential Failure → Adapter Fusion Solution.

### 3.3 Merging Strategy A: TIES-Merge

**TIES (Trim, Elect Sign, Merge)** is a structured merging algorithm designed to handle parameter conflicts between task-specific models:

**Step 1 — Trim (Pruning)**:
For each adapter, compute the task vector $\tau = W_{\text{fine-tuned}} - W_{\text{base}}$, then zero out all parameters below a density threshold $k$:
$$\tau'_i = \begin{cases} \tau_i & \text{if } |\tau_i| \geq \text{top-}k\text{ threshold} \\ 0 & \text{otherwise} \end{cases}$$

* **Density parameter**: $k = 0.5$ (retain top 50% of parameters by magnitude).

**Step 2 — Elect Sign**:
For each parameter position, tally the signs of the non-zero task vectors across adapters. The **majority sign** is elected:
$$s_i = \text{sign}\left(\sum_{t} \text{sign}(\tau'^{(t)}_i)\right)$$
Parameters whose sign disagrees with the elected sign are zeroed out.

**Step 3 — Merge**:
Average the remaining (sign-consistent, magnitude-filtered) task vectors:
$$\tau_{\text{merged}} = \frac{1}{|\mathcal{T}|} \sum_{t \in \mathcal{T}} \hat{\tau}^{(t)}$$

**Step 4 — Apply**:
Add the merged task vector back to the base model:
$$W_{\text{merged}} = W_{\text{base}} + \lambda \cdot \tau_{\text{merged}}$$
* **Scaling factor**: $\lambda = 1.0$

### 3.4 Merging Strategy B: Linear Average

The simplest possible merging approach — a direct arithmetic average of adapter weight matrices:

$$W_{\text{merged}}^{(l)} = \frac{1}{2}\left(W_{\text{Kannada}}^{(l)} + W_{\text{Telugu}}^{(l)}\right)$$

Applied independently to each LoRA matrix ($A$ and $B$) across all layers $l$.

**Properties**:
* No pruning, no sign election, no hyperparameters beyond equal weighting.
* Preserves the full magnitude of both adapters' contributions.
* Assumes that Kannada and Telugu adaptations are additively compatible.

### 4.4 Detailed Analysis

#### 4.4.1 Why Linear Average Outperforms TIES-Merge

```
  0          5         10        15        20        25
```

**TIES-Merge's Pruning Problem**:

TIES-Merge's trim step (Step 1) zeros out 50% of adapter parameters by magnitude. For Dravidian language adapters, this pruning is **destructive** because:

1. **Sparse Adaptation Signal**: Dravidian language adaptation activates a small, specific set of parameters (Unicode embedding adjustments, attention patterns for akshara sequences). Pruning 50% of these already-sparse signals removes critical fine-tuning information.
2. **Sign Conflict Resolution**: When Kannada and Telugu adapters move the same parameter in opposite directions, TIES-Merge's sign election forces one language's contribution to zero. For script-disjoint languages, many character-level embedding adjustments naturally have opposite signs (different Unicode blocks), causing excessive zeroing.

**Linear Average's Simplicity Advantage**:

Linear averaging preserves the full contribution of both adapters without any information loss. Its success suggests that:

1. **Orthogonal Subspaces**: Kannada and Telugu adaptations largely occupy orthogonal regions of the LoRA parameter space. Their sum doesn't cause destructive interference.
2. **Complementary Unicode Coverage**: Since Kannada (U+0C80–U+0CFF) and Telugu (U+0C00–U+0C7F) use completely different Unicode ranges, the adapter weights for character-level processing are naturally non-overlapping.

#### 4.4.2 Exceeding the Base Model

The Linear Average merge's bilingual average of **24.79** exceeds the untrained base model's **23.17** by **+1.62 chrF points**. This is significant because:

1. **Additive Capability**: The merged model doesn't just preserve base model capability — it enhances it. Both languages show improvement over their respective base model scores (Kannada: +1.93, Telugu: +1.31).
2. **Zero Additional Training**: This improvement comes at zero GPU training cost. The only compute was the CPU-based arithmetic averaging operation.
3. **Practical Deployment**: A single merged adapter can be loaded on top of the base model to serve both languages simultaneously, without maintaining separate model instances.

## 8. Recommendations for Future Work

### 8.1 Extending to More Languages
Linear Average merging's O(1) computational cost scales naturally to additional Dravidian languages (Tamil, Malayalam). Future work should:
* Train monolingual LoRA adapters for Tamil and Malayalam using Module 1's methodology.
* Merge 3- and 4-language adapters to test whether orthogonality holds across the full Dravidian family.

### 8.2 Weighted Merging
The current study used equal weights ($\frac{1}{2}$, $\frac{1}{2}$). Exploring non-uniform weights (e.g., $\frac{2}{3}$ for the dominant deployment language) could optimize for specific use cases without retraining.

### 8.3 DARE-TIES and Fisher-Weighted Merging
More advanced merging algorithms (DARE-TIES, Fisher-weighted averaging) may recover the signal that TIES-Merge lost through pruning, potentially outperforming Linear Average.

### 8.4 Continual Learning Mitigation
Applying Elastic Weight Consolidation (EWC), replay buffers, or progressive adapter freezing to sequential training could potentially address Module 2's catastrophic forgetting, though the computational cost may exceed adapter merging's simplicity.
